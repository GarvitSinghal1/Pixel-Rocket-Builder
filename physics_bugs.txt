[PHYSICS BUGS & MISIMPLEMENTED FEATURES]

1. [CRITICAL] Drag Reduction Ignored
   File: js/physics.js (Lines 270-278, 406)
   Bug: The `getDragCoefficient` function accepts a `maxDragReduction` parameter but the code to apply it is commented out. Consequently, adding nose cones or fairings (which provide `dragReduction`) has NO effect on the actual drag coefficient. The rocket experiences full blunt drag regardless of aerodynamic parts.

2. [MISIMPLEMENTED] Unimplemented Rotational Physics (Torque/Inertia)
   File: js/main.js (Lines 262-268), js/parts.js
   Bug: Although parts like 'Reaction Wheel' have a `torque` property and all parts have `mass`, the rotation logic in `main.js` simply increments `PHYSICS.rotation` by a hardcoded `0.05` radians per frame. It completely ignores Moment of Inertia and available torque, making rotation feel identical for a tiny probe and a massive heavy lifter.

3. [LOGIC] True Anomaly Normalization
   File: js/advanced.js (Line 125)
   Bug: The true anomaly calculation `Math.atan2(position.y, position.x) - Math.atan2(ey, ex)` can return negative values. It should be normalized to the range [0, 2π) for standard orbital representation.

4. [MISIMPLEMENTED] TWR Calculation uses Surface Gravity
   File: js/physics.js (Lines 698-709)
   Issue: The TWR (Thrust-to-Weight Ratio) always uses planetary surface gravity instead of local gravity at altitude. While standard for launch references, it results in misleading "Weight" values for rockets already in flight or landing on high-elevation terrain.

5. [REDUNDANCY] Redundant G-Force Logic
   File: js/physics.js (Lines 1428-1500)
   Issue: There are multiple conflicting ways G-force is "approximated" or "calculated" in the code. Lines 1428-1476 contain several commented-out or partial approximations before the "proper" fix at Line 1477. This creates confusion and potential for regression.

[DOCUMENTATION ERRORS]

6. [DOCS] Stagnation Temperature Discrepancy
   File: js/physics.js (Line 1774) vs (Line 445) vs index.html (Line 112)
   Error: The documentation commentary in `physics.js` at line 1774 claims the formula is `T_stag = T_ambient * (1 + 0.2 * Mach²)`. However, the implementation at line 445 (using recoveryFactor=0.9) and the hero text in `index.html` use `0.18 * Mach²`. While the code is technically more detailed (using gamma), the comments are inconsistent and misleading.

[HTML/CSS BUGS]

7. [UI] Telemetry Row Overflow
   File: html/simulator.html, css/styles.css
   Bug: The telemetry rows in the launch overlay (data-altitude, velocity, etc.) are fixed-width or flex-wrapped. On smaller viewports or with orbital data enabled, the "Advanced" telemetry rows can overflow the flight-data container, making them unreadable or obscuring the abort/stage buttons.

8. [ASSET] Logo Icon Missing
   File: html/simulator.html (Line 25)
   Bug: `simulator.html` references `../assets/favicon.png` as a logo icon inside the `<h1>`. If the user is on the landing page, the icon might be missing or wrongly scaled compared to the main logo.
